# GeekNews 초안 (news.hada.io)

> 채널: GeekNews — "Show GN" 톤. 1순위, 동시 유입 가능.
> 게시 전 체크: ① 배포 머신 상시가동 전환(`min_machines_running=1` — docs/promo/PLAN.md §4-A, Claude에게 "런치 모드 켜줘"로 요청 가능) ② 데모 영상이 현재 UI와 일치하는지 눈 확인 ③ 게시 중 재배포 금지(인메모리 방 전멸).
> 게시 타이밍: 평일(화~목) 오전 권장. 게시 후 댓글 질문에는 빠르게 답할 것 — GN은 작성자 응답이 스레드 체감을 좌우함.

## 제목 (택1)

- `Show GN: 복불복 — 설치 없이 폰으로 같이 하는 벌칙 정하기 파티 게임`
- `Show GN: DB 없이 서버 메모리만으로 만든 실시간 멀티플레이 파티 게임`

## 본문

시작은 회사 점심 후 커피 내기였습니다. 한 명이 자기 폰으로 룰렛을 돌리면 "네가 돌렸잖아"라는 (반쯤 진담인) 의심을 피할 수 없어서, **커피 사러 가기 전에 각자 자기 폰으로 직접 참여**하는 게임이 필요했습니다. 그게 이 프로젝트의 요구사항 전부였고 — 만들다 보니 범용 벌칙 정하기 파티 게임이 됐습니다.

호스트가 웹에서 방을 열면 QR이 뜨고, 참가자들은 앱 설치 없이 스캔해서 바로 입장합니다(2~30명). 미니게임 한 판으로 벌칙 당첨자가 정해지고, 모두의 화면에서 **똑같은 애니메이션이 같은 타이밍에** 재생됩니다.

게임은 6종입니다 — 마블 레이스 / 응원 마블 레이스 / 기울임 마블(자이로) / 동시탭 반응속도 / 일반 상식 퀴즈 / 넌센스 퀴즈.

**만들면서 구조적으로 재미있었던 점:**

- **서버가 결과의 유일한 권위자.** 클라이언트 입력을 진실로 신뢰하지 않습니다. 서버가 시드 기반으로 결과를 먼저 계산하고, 그걸 "리플레이 트랙"으로 한 번에 브로드캐스트합니다. 모든 클라이언트가 동일한 wall-clock 기준으로 같은 트랙을 재생하므로 화면이 갈리지 않고, 게임 내내 프레임을 스트리밍하는 게 아니라 시작 시 한 번의 브로드캐스트로 끝납니다.
- **마블 물리는 [lazygyu/roulette](https://github.com/lazygyu/roulette)(MIT)를 포팅했습니다.** 원본의 box2d-wasm 물리를 가져오되 `Math.random()`을 전부 주입식 시드 RNG로 치환해 **결정론화**한 게 핵심 델타입니다 — 같은 시드면 항상 같은 결과라, 서버가 한 번 시뮬레이션해 승패를 확정하고 클라이언트는 그대로 그립니다. 색깔별 승률이 치우치지 않는지 검증하는 공정성 스크립트도 넣었습니다. (원작자께 감사드립니다 — 출처는 NOTICE에 명시)
- **예외가 하나 있는데, 기울임 마블입니다.** 폰 자이로로 자기 구슬을 조종하는 게임이라 미리 계산이 불가능해서, 이 게임만 서버에서 물리를 실시간으로 돌리고 위치를 스트리밍합니다. "기본은 precompute+replay, 입력이 게임 중에 들어오는 경우만 live"라는 두 계층이 자연스럽게 생겼습니다.
- **DB가 없습니다.** 방·플레이어 상태는 전부 서버 프로세스 메모리(`Map`). 재시작 = 초기화가 정상 동작입니다. 일회성 파티 게임이라 영속 저장은 가치보다 그룹 간 격리 리스크가 크다고 판단했습니다. 부작용도 있었는데 — 결과 공유 이미지를 서버 OG 라우트로 만들 수가 없어서(공유 시점엔 방이 이미 GC됨), 클라이언트 캔버스에서 그려 Web Share API로 내보내는 쪽으로 풀었습니다.
- **공개 운영 가드.** 단일 인스턴스(Fly shared-cpu-1x/512MB) 전제라 전역 동시 방 수 상한 + 방 생성 IP 레이트리밋 + 소켓 플러드 가드로 OOM/남용을 막고, 초과 시 503/429로 degrade합니다. scale-to-zero라 유휴 비용은 사실상 0입니다.

스택: Next.js 16(App Router) + 커스텀 Node 서버 + Socket.IO(동일 포트), TypeScript. 한국어 UI, MIT 오픈소스.
